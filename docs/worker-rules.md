# Правила задач для воркеров (решение пользователя 2026-11-10, экономия токенов)

Расход идёт в основном на повторное чтение контекста: воркер к концу держит 300–400 тыс. токенов и делает 300–500 шагов. Поэтому:

1. **Короткие задачи.** Одна задача — один экран или одна система, ~100 шагов. Большое делится на последовательные задачи с коммитом в конце каждой. В спеке — явный конец («готово, когда …»).
2. **Скриншоты — по бюджету.**
   - `tools/shot.sh <имя> <папка>` — обрезка до вьюпорта игры, 800 px (`full` — всё окно).
   - Не больше ~10 открытых снимков на задачу: снимать в ключевых точках (итог экрана, спорное место), а не после каждой правки.
   - Серии (`tools/burst.sh`) не открывать по одному: выбрать до 9 кадров и склеить `tools/sheet.sh out.jpg кадры…` — одно изображение.
   - Проверку раскладки сначала делать числами (`execute_luau`: Visible, AbsolutePosition/Size, тексты), снимок — для финального взгляда.
3. **Не ждать в цикле.** Долгие тесты — один запуск с таймаутом, без опроса каждые N секунд.
4. **Модели:** как раньше — тяжёлое (дизайн, визуальный перенос, архитектура) на Opus, рутина на Sonnet по решению директора.

Директор ссылается на этот файл в каждой спеке: «Правила: `docs/worker-rules.md`».
