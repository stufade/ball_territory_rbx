# Сетевой протокол M1

Модули: `ReplicatedStorage.Shared.Net` (имена, перечисления, лимиты, типы), `Net.Snap` (кодек снимков на `buffer`, чистый), `Net.Remotes` (экземпляры; сервер создаёт папку `ReplicatedStorage.Remotes`, клиент ждёт). Бой считает сервер, 30 шагов/с времени матча; клиент только рисует и шлёт ввод.

**Координаты.** Шары, события и клоны — в клетках поля правил (`x` вправо, `y` вниз, дробные). Клетка арены `i = floor(x) - ox`, `j = floor(y) - oy`; `ox, oy, w, h` приходят в `start` (дуэль: 4, 3, 16×14; ffa: 0, 0, 24×20). Индекс клетки в снимке `c = j*w + i` (с нуля).

| Remote | Тип | Куда | Формат | Частота |
|---|---|---|---|---|
| `Snap` | UnreliableRemoteEvent | S→C участникам и зрителям арены | `(buf: buffer)` пакет снимка, ≤ 900 Б | 15/с, бой |
| `Match` | RemoteEvent | S→C участникам арены | `(kind: string, data: table)` | по событию, `ev` ≤ 15/с |
| `State` | RemoteEvent | S→C одному игроку | `(st: Net.State)` полное состояние экрана | при смене |
| `Input` | RemoteEvent | C→S | `(kind: number, dx: number?, dy: number?)` | ≤ 20/с |
| `Action` | RemoteEvent | C→S | `(verb: string, arg: number?)` | ≤ 4/с |
| `Party` | RemoteEvent | S→C одному игроку | `(view: Net.PartyView)` вся party игрока и входящие приглашения (M1.6) | при смене |
| `Profile` | RemoteEvent | S→C одному игроку | `(view: Net.ProfileView)` уровень, опыт, коллекция, буст (T2.2) | при загрузке, `hello`, смене |

**`Match`** (`data.id` — номер матча; сообщения чужого или старого `id` клиент игнорирует):
- `start` `{id, arena (Model.Name), aid (номер арены для `watch`), mode ("duel"|"ffa"|"intro"|"tutor"), round (с), ox, oy, w, h, you (e или nil), seats = {{e, name, userId (0 = бот), side}}, key: buffer, aim?: {dx, dy}}` — `key` — полный кадр клеток (`Snap.applyKey`); `aim` — своё направление в фазе `aim` (только сидящему игроку); `view = true` (M1.6) — получатель зритель с площадки, а не участник: без HUD, камеры и ввода. Приходит в начале каждого раунда.
- `unview` `{id}` (M1.6) — зрителю: этот матч больше не шлётся (отошёл от арены или арена закрылась); клиент убирает поле с доски.
- `aim` `{id, dx, dy}` — только владельцу шара: принятый сервером прицел в фазе `aim`, уже в том виде, как шар полетит (`Rules.aimDir`). До старта сервер держит прицелы отдельно от правил и применяет при `launch`, чужой прицел не видит никто.
- `ev` `{id, list = {{kind, d}}}` — события правил с прошлого снимка, по порядку (`docs/rules.md`, `Rules.drain`: `power`, `rx` (`d.k` — реакция), `hit`, `ko`, `steal`, `spawn`, `prompt`, `final`, `ready`, `launch`, `redirect`, `tap`, эффекты сил). `wall` не шлётся.
- `phase` `{id, ph ("aim"|"play"|"rend"), endsAt}` — прицел до старта, бой, пауза после раунда.
- `hint` `{id, k}` — подсказки запасного первого раунда (`Config.TUTORIAL = false`): `aim`, `power` (сила заряжена), `react` (первая реакция), `final`. Обучение их не шлёт.
- `tut` `{id, s, k, n, wait, ...}` (T2.1) — подсказка обучения: `s` — сцена `A`..`D`, `k` — что показать, `n` — номер, `wait = true` — ждём действия игрока. `A`: `react`, `boom` и `wild` `{rx, e, l (слой)}` (формула), `tap` (wait: ответ `Action tut n`), `out`. `B`: `power` (wait: ответ — обычный `Input power`), `grab`. `C`: `dir {e, x, y (враг), fx, fy (свой шар), retry}` (wait: ответ — обычный `Input dir`), `go`, `miss`, `ko`. `D`: `final`. `out` — переход: клиент затемняет экран, следующая сцена приходит новым `start`. Без ответа 20 с обучение делает действие само.
- `round` `{id, win (сторона 0/1, -1 ничья), a, b, pa, pb, lost = {{e},{e}}, score = {s0, s1}}` — конец раунда дуэли: `a`, `b` — шары (e) сторон 0 и 1 в этом раунде, как в веб-логе; `pa`, `pb` — земля сторон в % арены; `lost` — выбывшие шары сторон; `score` — выиграно раундов стороной 0 и 1.
- `end` `{id, mode, winner (e в ffa/intro, сторона в дуэли, -1 ничья), places = {{e, pct, kills, powers}}}` — конец матча; затем `State` = `result`, потом `lobby`.

**`Snap`** — `Snap.decode(dec, buf)`; пакеты старше последнего `seq` отбрасываются. Тип 1 (кадр): `u8 type, u8 ep (номер матча mod 256, пакеты чужого `ep` отбрасываются), u16 seq, u32 t (мс матча), u16 pu (CHOOSE DIRECTION до, 0 = нет), u8 st (1 финал, 2 старт, 4 замедление), u16 rx, u8 nb, nc, nk, nu`; шары по 26 Б: `e, x, y (u16 ×1000), ang (u16), hp, alive, charge (u8 ×250), flags, dx, dy (i8 ×127; до старта, бит `st` 2 не стоит, всегда 0 — прицелы скрыты), hole (u8 ×50 с), hx, hy, sx, sy (u16 ×1000), powers, kills, cnt (u16 земля в клетках)`; `hp` 0–100; клоны, бомбы, пузыри по 5 Б (`x, y, e` / `x, y, t ×50`); затем клетки: `u16 refStart, u8 refN, refN × u16` — полное значение клеток подряд (обход всего поля за 8 кадров) и `u16 nd, nd × (u16 c, u16 v)` — изменённые за 2 последних кадра. Тип 2 — продолжение дельт того же `seq`, если кадр больше 900 Б. Тип 3 — полный кадр (`key`). Значение клетки `v`: биты 0–4 владелец+1 (0 — ничья), 5–8 верхний слой (индекс в `Config.TOP`, 0 — нет), 9–12 угасание 0–9.

**`State`** `{ph, mode?, endsAt?, ...}` (`endsAt` — `workspace:GetServerTimeNow()`):
- `lobby` `{first: bool, glow?}` — выбор режима; `first` — игрок ещё не играл (первый вход идёт сам, без лобби); `glow = "play"` (T2.1) — после обучения подсветить PLAY, снимается при первом поиске.
- `queue` `{mode, endsAt, humans}` — ищем людей 5 с, потом боты; `humans` — сколько людей уже в очереди.
- `pick` `{mode ("intro"|"ffa"), options = {e}, taken = {e}, endsAt}` — выбор шара: intro — 4 стартовых, ffa — все свободные.
- `draft` `{me (своя сторона 0/1), turn (сторона 0/1), teams = {{e},{e}}, offer = {e,e,e} (только в свой ход), any (бесплатный «Любой шар» не взят), anyLeft (сколько «Любых шаров» осталось), own? = {e} (T2.2: своя коллекция, nil = все шары), names, endsAt}`. Предложение — из своих свободных шаров; если их меньше 3, добирается из всех свободных. «Любой шар» — только из своей коллекции. Бот берёт шары, которых нет у человека-соперника, пока таких хватает.
- `choose` `{me (сторона 0/1), keep (свой шар, если остаёшься с ним, иначе -1), left = {e}, rival (шар победителя или -1), blind, teams, lost, endsAt}` — выбор шара на раунд дуэли (10 с). Выбирает только сторона без шара (проигравший; после ничьей и в первом раунде обе вслепую). Победитель получает `keep ≥ 0` и пустой `left`, его `choose` отбрасывается.
- `match` `{mode, arena}` — идёт бой, детали в `Match`. `wait` `{mode}` — нет свободной арены.
- `result` `{mode, win: bool, endsAt, xp?, xpMult?, coins?, friend?, afk?, streak?}` — экран победы/поражения, по `endsAt` сервер вернёт в `lobby`; `xp` (T2.2) — опыт за матч уже с бустом, `xpMult` — множитель (2 при бусте; с другом ×1,5: 1,5 или 3); M3.1: `coins` — монеты за матч вместе с серией (без книги и заданий), `friend = true` — засчитан бонус друга, `afk = true` — в каком-то раунде не было ни одного ввода: ни монет, ни опыта, `streak` — побед подряд в дуэли.
- `reward` (T2.2) `{balls = {e×4}, legend (e), pool = {e}, boost (с), endsAt}` — награда после первого обучения: 4 стартовых, легендарный бесплатной рулетки (сервер уже выдал и сохранил его, клиент только показывает остановку ленты из `pool` на `legend`), секунды 2x опыта. Экран стоит вместо `lobby`, пока клиент не пришлёт `Action claim` (или до `endsAt`, 90 с), затем `lobby {glow = "play"}`. Во время `reward` поиск не принимается.

**Тест всех шаров** (`Config.TEST_ALL_BALLS`, с T2.2 по умолчанию `false`; в Studio — атрибут `ServerScriptService.DebugAllBalls = true`): стартовый выбор `pick intro` — все 27, «Любой шар» на каждый пик драфта (`anyLeft` = 3), `own = nil`. Выключен — драфт и выбор на четверых из коллекции профиля (`pick ffa` `options` — свои свободные; своих свободных нет — все свободные), 1 «Любой шар» за дуэль.

**`Input`** `kind` из `Net.Input`: `1 aim (dx, dy)` — прицел в фазе `aim` (ответ владельцу — `Match aim`); `2 launch (dx?, dy?)` — готов, старт, когда готовы все люди или вышло время; `3 dir (dx, dy)` — новое направление в бою (окно CHOOSE DIRECTION или финал); `4 power`. `dx, dy` — направление в осях поля правил, модуль не важен.
**`Action`** `verb` из `Net.Action`: `queue (1 дуэль, 2 ffa)`, `cancel`, `pick (e)`, `draft (e из offer)`, `any (e — любой свободный, 1 раз за дуэль)`, `choose (e из left)`, `watch (aid)` — зритель арены (отладка), `leave` — из зрителей или результата в лобби, `tut (n)` (T2.1) — тап по ждущей подсказке `n` обучения, `tutor` (T2.1) — HOW TO PLAY: обучение заново (во время обучения — с начала), `claim` (T2.2) — экран награды досмотрен, `daily` (M3.1) — забрать награду входа (раз в UTC-сутки, решает сервер, повтор игнорируется), `hello` — клиент готов (сервер повторяет и `Party`) (UI подключён): сервер повторяет текущий `State`, таймер выбора стартового шара первого входа идёт с `hello` (без него — через 20 с после входа).

**Зрители (M1.6).** Сервер раз в 0,25 с смотрит, где стоит каждый человек на площадке (не в матче и не в первом выборе), и делает его зрителем ближайшей живой арены (`Watch.luau`): расстояние до центра доски, глубина z считается с коэффициентом 0,35, войти ближе 32, выйти дальше 40. Зритель получает `start` (`view = true`), снимки, события, `round`, `end` этой арены, при уходе — `unview`. Одна арена на человека, не больше 6 зрителей на арену (`Config.WATCH_MAX`). Трафик зрителя — одна арена: в среднем 2–4 КБ/с, пик 9 КБ/с (как у участника), ниже лимита 20 КБ/с (`tests/party`: 0,2–20 КБ/с). `watch (aid)` осталось для отладки, но проверка по расстоянию его перебивает.

**Party (M1.6)**, `Action` (аргумент — UserId, где нужен): `pcreate` — своя party (хозяин); `pinvite (userId)` — пригласить человека этого сервера (любой участник; приглашение живёт 30 с, одному человеку не чаще раза в 3 с, у party не больше 6 приглашений); `paccept (userId пригласившего)`, `pdecline (userId)`; `pleave` — выйти (хозяином становится следующий, пустая party исчезает); `pkick (userId)` — только хозяин; `pplay (1 дуэль, 2 ffa)` — только хозяин, все участники свободны: дуэль — ровно двое друг против друга, без ботов и чужих; ffa — вся party одной записью очереди, свободные места — очередь 5 с, затем боты. `queue` участника party из двух и больше — у хозяина это `pplay`, у остальных отказ «The host starts the game». `cancel` любого участника снимает с поиска всю party. Смена состава party во время поиска снимает её с поиска. `pfriends` — хозяин открыл окно приглашения друзей: 10 минут друзья по ссылке попадают в party.
`Party` → `{id?, host?, members = {{userId, name, busy}}, invites = {{from, name, endsAt}}, note?}` — `id = nil`: не в party; `busy` — в матче; `note` — короткое сообщение показать один раз.
**Приглашение друга** (`SocialService:PromptGameInvite`, `ExperienceInviteOptions.LaunchData` = JSON `{h = UserId хозяина, j = JobId}`): зашедший с такими данными на тот же сервер (`j` = `game.JobId`) попадает в party хозяина, если хозяин её не распустил, окно `pfriends` открыто и они друзья (`IsFriendsWithAsync`); на другом сервере — `TeleportService:TeleportAsync` с `TeleportOptions.ServerInstanceId = j` и `TeleportData.btParty`, после телепорта повторного нет; ошибки (`TeleportInitFailed`, полный сервер) — `note`. В Studio не проверяется (NOT VERIFIED).

**Защита** (сервер): неверный тип, NaN, ±inf, нецелый `e`, чужая фаза, чужое место, нет своего шара — пакет молча отбрасывается. Шар игрока сервер берёт из его места, клиент `e` в бою не шлёт. Лимиты (`Net.Limits`): `Input` 20/с при запасе 10, `Action` 4/с при запасе 6, `dir` в финале не чаще раза в 0,2 с реального времени (и правила: 0,2 с времени матча). Направление обрезается до ±50.

**Бюджет** (`lune run tests/net`, бои ботов): дуэль — снимок в среднем 140 Б, максимум 531 Б, 2,1 КБ/с (пик 8 КБ/с), события `ev` ≈ 0,1 КБ/с; ffa — 275 Б, максимум 606 Б, 4,1 КБ/с (пик 9 КБ/с), `ev` ≈ 0,2 КБ/с. Лимит M1-7 — 20 КБ/с на клиента.

**Отладка** (атрибуты `ServerScriptService`): `DebugBotMatches = true` — матчи ботов на всех свободных аренах без остановки, раз в 10 с в консоли `[BT] stats`: шаги правил в секунду по аренам (30 при обычной скорости, меньше в замедлении после новой реакции), `capped` — кадры, где сервер не успел, время кадра сервера. `DebugSide = 1` — одиночный игрок в дуэли садится на сторону 1 (правое место), бот на сторону 0: проверка клиента за обе стороны. `DebugFakeFriend = true` (M1.6) — фальшивый второй человек «FAKE FRIEND» (UserId −999, без персонажа и клиента): сразу принимает приглашения в party, в матче бездействует (выбор по таймерам); проверка party и «дуэли друг с другом» в Studio, где человек один. `DebugInputLog = true` — лог каждого `dir`/`power` (принят или отброшен, в финале — интервал тапа). В консоли `[BT] M1-4 first round ...` — время от `hello` и от входа до первого раунда.

**Обучение (T2.1).** Первый вход (нет флага) — сразу сессия `tutor` на дуэльной арене после `hello` (без него — через 20 с): `State match {mode = "tutor"}`, 4 сцены, каждая — новый `start` (без фазы прицела, сразу `phase play`), затем `end` и `result`. Игрок — Огонь (0), бот — Лёд (1). Сцены — обычные правила, поставленные `Logic/Stage.luau` (позиции, направления, слои, земля, таймеры); время сцены стоит (`Runner.scale = 0`), пока игрок не сделает действие. Финал D: раунд 15 с, весь — FINAL (`finalAt = 0`), у игрока стартовое пятно земли радиусом 4 клетки, бот (`Logic/TutorBot.luau`) не жмёт силу, кружит над своей землёй и отворачивает от игрока; `lune run tests/tutor 1000` — 1000/1000 побед, отрыв 5–65 %. Флаг — атрибут игрока `TutorialDone` и память сервера по UserId (`src/server/Tutorial.luau`: `isDone`, `setDone`, `onDone(fn(player, {first, seconds}))`, `ready(player)` — хук T2.2 для загрузки профиля). Повторный вход на этот сервер — сразу `lobby`. `Config.TUTORIAL = false` возвращает старый выбор стартового шара и раунд с подсказками.
**Отладка обучения** (атрибуты `ServerScriptService`): `DebugTutorSpeed` (0–4) — скорость обучения, 0 — стоп; `DebugTutorTour = true` — обучение идёт само и стоит по 3 с в каждой сцене для снимков (`docs/shots/t2.1/README.md`).

**Профиль (T2.2).** `src/server/Profiles.luau` (сервис), `Store.luau` (запись с блокировкой), `Logic/Progress.luau` (чистые правила, `lune run tests/profile`). DataStore `Profiles1`, ключ `u<UserId>`, только `UpdateAsync`. Запись `{data, lock = {s = сессия, t = os.time()}, saved}`; `data` — `{v = 1, tut, rewarded, played, balls = {e}, level, xp (внутри уровня), boostUntil (os.time), matches, wins}`, миграция `Progress.migrate` (v0 `{done, owned}`, мусор, дубли, новая версия читается по полям). Загрузка берёт блокировку: чужая живая — ждём до 15 с и забираем (старый сервер больше не пишет: `save` проверяет, что блокировка наша), старше 600 с — сразу. 5 повторов с паузой 1–8 с. Сохранение: при выходе (с освобождением), раз в 60 с, через ≥ 7 с после награды или нового уровня, в `BindToClose`. Нет доступа (Studio без API, неопубликованное место) — профили в памяти сервера и одно предупреждение `[BT] profiles: DataStore unavailable ...`; не загрузился после повторов — играет на новом профиле, который не сохраняется. Обучение ждёт загрузки (`Tutorial.ready`), сохранённый `tut` — сразу площадка (`Lobby.loaded`).

(GetServerTimeNow), boostMult = 2, levelBalls = 9, news? = {{level, e?, coins?, crystals?}}}` — `news` только в сообщении, где уровень вырос (клиент показывает NEW BALL!; уровни 10+ приходят с `coins`/`crystals` без шара). **Монеты** (`Economy.COINS`, `Logic/Earn.luau`, считает сервер в `Session.finish`): дуэль 25, +25 за победу; на четверых 11, +15 за 1-е место; реакция своих шаров 2 (до 10), KO 3 (до 9). AFK — раунд без единого ввода (`aim`, `launch`, `dir`, `power`; `Runner.acted`): ни монет, ни опыта, ни заданий, ни книги, серия не меняется. Друг Roblox в том же матче (`IsFriendsWithAsync`, кэш при входе, `Friends.luau`; не бот, оба не AFK): +25 % монет и ×1,5 опыта, первые 20 таких матчей за UTC-сутки (`friend`). x2 монет — геймпасс M3.2 (пока `pass2x = false`). Серия побед в дуэли: 3 → 50, 5 → 100, 10 → 300, проигрыш обнуляет, матчи на четверых не считаются. Задания: по одному лёгкому, среднему и трудному из `Economy.QUESTS.pool` в сутки, 60 / 80 / 120, за все три +50. Книга: 25 за новую реакцию, каждые 10 — 10 кристаллов, все 42 — 1000. **Косметика.** `Action look` — третьим аргументом id из `Economy.LOOKS`, сервер списывает монеты и отказывает, пока уникальных шаров меньше 27 или не хватает монет; повтор того же id не списывает. `Action wear` — тот же id, `arg` — шар только для скина. В профиле `looks = {id}`, `worn = {skin, trail, force, frame, podium, ko, ball}`. `Profile.shelf = {n, need = 27, owned, on, robux}` — в `robux` только asset id > 0. Чек продукта с таким id вызывает `Looks.grant`: до 27/27 это `NotProcessedYet` без записи PurchaseId. `Analytics.look` (id, `coins` или `robux`). Бой эти поля не читает.
**Отладка профиля** (атрибуты `ServerScriptService`): `DebugAllBalls = true` — все 27 у всех; `DebugFreshProfile = true` — входящие получают новый профиль, который не сохраняется (первые минуты заново при включённом DataStore); `DebugXp = n` — n опыта всем один раз (NEW BALL!); `DebugDay = n` (M3.1) — часы профилей этого сервера сдвинуты на n суток: вход и задания следующего дня без ожидания 00:00 UTC (в живой игре не ставить).
